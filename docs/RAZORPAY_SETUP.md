# Razorpay — Setup Guide (do this before/around integration)

This lists **every key and setting** the site needs to accept payments, where to
get each, and how. Our flow uses **Razorpay Standard Checkout** (`checkout.js`) +
the **Orders API** + a **Webhook** — no dashboard plugin required.

> Order of operations: you can build & test everything in **Test Mode** now.
> **Live Mode** needs account activation (KYC) — start that in parallel since it
> takes a few days.

---

## What we'll need (the end state)

Four values go into `.env.local` (and later into Vercel):

| Env var | Value | Exposed to browser? |
|---|---|---|
| `NEXT_PUBLIC_RAZORPAY_KEY_ID` | Key ID (`rzp_test_…` / `rzp_live_…`) | **Yes** (public — safe) |
| `RAZORPAY_KEY_ID` | Same Key ID (used server-side) | No |
| `RAZORPAY_KEY_SECRET` | Key Secret | **No — secret** |
| `RAZORPAY_WEBHOOK_SECRET` | The secret you type when creating the webhook | **No — secret** |

The Key ID is intentionally in two vars: the browser needs it to open Checkout,
and the server needs it to create orders. The **Key Secret** and **Webhook
Secret** never touch the browser.

## Step 1 — Create a Razorpay account
1. Sign up at <https://dashboard.razorpay.com/signup> (use the editor's business email).
2. You land in the Dashboard, defaulting to **Test Mode** (toggle top of the menu).

## Step 2 — Generate API Keys (Test Mode first)
1. Ensure the mode toggle shows **Test Mode**.
2. Go to **Account & Settings → API Keys** (under "Website and app settings") → **Generate Key**.
3. A dialog shows your **Key ID** and **Key Secret**.
   - The **Key Secret is shown only once** — click **Download Key Details** and store it safely (password manager).
   - Only the Key ID stays visible on the Dashboard afterward.
4. Test keys look like `rzp_test_XXXXXXXXXXXXXX` (Key ID) + a secret string.
5. Put them in `.env.local`:
   ```
   NEXT_PUBLIC_RAZORPAY_KEY_ID=rzp_test_XXXXXXXXXXXXXX
   RAZORPAY_KEY_ID=rzp_test_XXXXXXXXXXXXXX
   RAZORPAY_KEY_SECRET=<the downloaded secret>
   ```
> Regenerating keys later requires OTP (2FA) and **invalidates the old keys**.

## Step 3 — Turn on Automatic Capture
So authorized payments actually get captured & settled (otherwise Razorpay
auto-refunds uncaptured payments within ~3 days):
1. **Account & Settings → Payment Capture**.
2. Next to **Automatic capture**, click **Change** → select **immediately** (or your window) → **Save**.

(Our server also verifies each payment right after checkout, but auto-capture is
the safety net.)

## Step 4 — Create a Webhook
The webhook is our **source of truth** for confirming payments.
1. Go to **Account & Settings → Webhooks** → **Add New Webhook** (Test Mode has its own webhooks, separate from Live).
2. **Webhook URL** — the deployed endpoint the app exposes:
   ```
   https://<your-domain>/api/razorpay/webhook
   ```
   - Must be publicly reachable over **HTTPS (port 443)**.
   - For **local testing**, expose your dev server with a tunnel (e.g.
     `ngrok http 3000` or `cloudflared`) and use that HTTPS URL, **or** use the
     "Test webhook" button in the Dashboard once created.
3. **Secret** — type any strong random string **you choose** (this is *your*
   secret, not generated by Razorpay). Save the exact same value as:
   ```
   RAZORPAY_WEBHOOK_SECRET=<the string you typed>
   ```
4. **Alert Email** — an email for delivery-failure alerts.
5. **Active Events** — tick at minimum:
   - `payment.captured` ✅ (payment succeeded & captured)
   - `payment.failed` ✅ (payment attempt failed)
   - `order.paid` ✅ (order fully paid)
   - *(optional)* `payment.authorized`
6. Click **Create Webhook**.

> How verification works (handled in code): Razorpay signs each webhook with your
> secret and sends `X-Razorpay-Signature`. The server recomputes an
> **HMAC-SHA256 of the raw request body** and compares — so the webhook route
> must read the **raw body** (no JSON pre-parsing).

## Step 5 — Account Activation / KYC (required for Live payments)
Do this early; it gates Live keys and settlements.
1. Dashboard → complete **Account Activation** / **KYC**. Typically needed:
   - Business/entity type & PAN
   - Bank account for settlements
   - Address / identity proof
   - **Website/app details** — your live URL must be submitted and **verified
     (within ~3 working days)** before Live keys can be generated.
2. After approval, switch to **Live Mode** and repeat **Step 2** to get
   `rzp_live_…` keys, and **Step 4** to create a **Live** webhook (Live and Test
   webhooks are separate). Swap the `.env` values for production.

> If you go Live without replacing the Test keys, customers see a success screen
> but **no money is captured/settled** — always swap to `rzp_live_…` in prod.

## Testing (Test Mode)
Once integrated, use Razorpay's test instruments:
- **Card:** `4111 1111 1111 1111`, any future expiry, any CVV, any name.
- **UPI success:** `success@razorpay`  •  **UPI failure:** `failure@razorpay`
- Amounts are sent in **paise** (₹500 → `50000`) and currency `INR` — the code
  handles this; just enter rupee prices in the CMS/packages.

## Quick reference — where each value comes from
| Need | Dashboard location |
|---|---|
| Key ID + Key Secret | Account & Settings → API Keys → Generate Key |
| Webhook Secret | You choose it in Account & Settings → Webhooks → (Secret field) |
| Auto-capture | Account & Settings → Payment Capture → Change |
| Live keys | Same as API Keys, but in **Live Mode** (after KYC) |

## What the integration will add (next phase, for context)
- `razorpay` npm package (server) + `checkout.js` (client, lazy-loaded).
- `POST /api/razorpay/order` → creates an order (amount validated server-side).
- `POST /api/razorpay/verify` → verifies checkout signature (HMAC-SHA256).
- `POST /api/razorpay/webhook` → verifies `X-Razorpay-Signature` on the raw body,
  confirms the order, triggers the receipt.
- Success/failed pages already exist (`/payment/success`, `/payment/failed`).
